# INTEGRITY

The hash of the downloaded bytes doesn't match the declared `integrity`. The code doesn't run.

## Causes

- The JS was changed after the build (CDN, proxy or attack).
- The `integrity` registered in the host is from an old build.
- The server changes the bytes (minification, line ending changes, inserting a BOM).
- The value isn't in SRI format: `sha256-...`, `sha384-...` or `sha512-...`.

## How the hash is checked

- The hash is computed over the exact bytes of the response, as in the browser.
- With several hashes (`sha256-A sha384-B`), the strongest algorithm wins. The file must match one of that algorithm's hashes.
- The error message shows the expected and the actual hash.
- Where the browser checks the hash itself (import map or modulepreload with `integrity`), a failure makes the library try again through `blob:`, which checks the bytes of the single file and throws this error if they don't match.
- CSS with a hash in the manifest is checked too. CSS that doesn't match isn't applied, but the remote mounts.

## How to fix

Use the `vitral.json` generated by the `vitral/vite` plugin: it carries the build's hash and changes on every deploy. If you declare `integrity` in the host, update the value together with the remote's deploy.
