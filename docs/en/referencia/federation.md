# vitral/federation

Mounts, in a vitral host, a remote that is still on Module Federation. It's for migrating one remote at a time: the host already uses `<Remote>`, and the remote keeps publishing `remoteEntry.js`.

```ts
federationRemote(url: string, options?: FederationOptions): RemoteEntry
```

`url` is the remote's `mf-manifest.json` (generated by `@module-federation/enhanced`, Rspack and `@module-federation/vite`) or, without a manifest, the `remoteEntry.js`.

## Usage

```tsx
import * as React from 'react'
import * as ReactDOM from 'react-dom'
import { configure } from 'vitral'
import { federationRemote } from 'vitral/federation'
import { Remote, reactRemote } from 'vitral/react'

configure({
  remotes: {
    cart: federationRemote('https://cdn.example.com/cart/mf-manifest.json', {
      adapt: (m) => reactRemote(m.default),
      shared: { react: { version: React.version, modules: { react: React, 'react-dom': ReactDOM } } },
    }),
  },
})

<Remote name="cart/Cart" props={{ userId: 42 }} />
```

Each part of Module Federation's `exposes` becomes `name/Part`. Modules without UI come through `loadModule('cart/api')`.

## Options

| Option | What it does |
| --- | --- |
| `adapt(module, key)` | Turns the exposed module into a remote with `mount` (e.g. `(m) => reactRemote(m.default)`). Returning `undefined` leaves the module as is. A part that already exports `mount` doesn't go through here |
| `shared` | Dependencies the host offers the remote, in the format of `configure`'s `dedupe`. Each specifier enters the share scope with the group's version. The remote uses the host's if it fits; otherwise, its own copy |
| `expose` | The part mounted by `<Remote name="cart">`, without `/`. Default: the manifest's only part |
| `global` | Without a manifest: name of the container's global variable (`library.type: 'var'`). Without this option, the URL is imported as an ES module |
| `allowedOrigins` | Origins `remoteEntry.js` can come from, besides the manifest's origin. `['*']` allows everything |

With `adapt` and a React component, pass the host's React in `shared`. Otherwise, the remote's component runs with another copy of React, and hooks break.

## How it works

1. Downloads `mf-manifest.json` (no cache) and builds the `remoteEntry.js` URL with `publicPath`, `remoteEntry.path` and `remoteEntry.name`.
2. Loads `remoteEntry.js`: with `<script>` and `window[globalName]` when `remoteEntry.type` is `global` or `var`; with `import()` when it's `module` or `esm`. If the Module Federation host already loaded the global container, it's reused.
3. Calls `container.init(shareScope(shared))` once per manifest and `container.get('./Part')` once per part. `shareScope` is also exported, for those who call `init` by hand.

## Limits

- No SRI: `mf-manifest.json` doesn't carry file hashes. `configure`'s `allowedOrigins` doesn't apply here; the option's `allowedOrigins` does.
- `getPublicPath` (JS code in the manifest) isn't supported, because it would require `eval`. Use `publicPath`.
- The CSS is loaded by the Module Federation runtime, into `document`. It doesn't work with `isolate="shadow"`.
